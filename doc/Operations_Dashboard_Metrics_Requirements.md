## 1. 審核結論（先看這段）

整體指標方向正確，且與現有 PRD 的營運看板目標一致：**按航班日期 × 航段彙總行李預報，輸出重量／體積規劃參考，而非自動釋放貨艙**。

建議審核時採納的分級：

| 分級 | 指標 | 理由 |
| --- | --- | --- |
| **P0 必做** | 航班日期與航段、預計乘機人數、已／未申報人數、已知件數、預計總重、估計體積、資料來源標籤、重量／體積規劃餘量、資料更新時間、缺口警示、申報覆蓋率 | 已寫入 PRD OPS01–OPS03；演示與驗收（AC04–AC07）直接依賴 |
| **P0 建議補強** | 艙位壓力指數（Capacity Stress Index） | 把「重量瓶頸 vs 體積瓶頸」一次講清楚，適合看板主視覺 |
| **P1 可做** | 高信賴度數據佔比、可供商用載貨空間、航班營運風險評級 | 有業務價值，但依賴預算／貨物分配輸入完整度 |
| **P2／需重定義** | 動態調整同步延遲率（Real-time Sync Latency） | 本質是**系統觀測指標**，不是營運業務 KPI；不建議與申報覆蓋率並列為「看板主指標」 |
| **勿過度承諾** | 延誤風險指數、艙位配置優化建議 | 需額外航班準點／配載規則；OAG 僅能提供部分輔助欄位 |

**關鍵原則（審核請確認是否同意）：**

1. 看板輸出為「規劃參考」，最終配載仍由航司流程確認。
2. 未申報旅客不得當作 0；必須用基線補估，並標記資料來源。
3. 同一件行李只計一次（旅客申報／服務訂單／實測共用同一 `itemId`）。
4. 重量與體積是雙約束；餘量為負或資料不足時必須警示，不得顯示「已確定可售空間」。
5. OAG 提供航班維度與機型／座位等**航班側上下文**，不提供行李件數／重量／體積；行李指標來自 Plume Light 申報與營運預算輸入。

## 2. 看板目標與使用者

| 項目 | 定義 |
| --- | --- |
| 主要使用者 | 國泰員工（裝載規劃／貨運分配相關角色）；頁面須標示「僅限國泰員工」 |
| 核心問題 | 本航段托運行李大概佔多少重量與體積？有多少是真實申報？還剩多少規劃餘量給商用貨物？ |
| 成功標準 | 旅客改重後，預測總重與餘量同步更新；覆蓋率、補估與實測可區分；缺口／負餘量可見 |
| 非目標 | 自動銷售貨艙、替代正式配載系統、宣稱增加飛機物理容量 |

## 3. 資料來源邊界

### 3.1 本產品（Plume Light）

| 資料 | 說明 |
| --- | --- |
| 已保存行李申報 | 乘機人、航段、件數、重量、尺寸、更新時間、版本 |
| 系統基線補估 | 未申報客群的預設人均行李假設（演示例：30 kg／人） |
| 實測（若有） | 取件或機場稱重後覆寫規劃值，保留與預報差異 |
| 營運預算輸入 | 航段重量預算、體積預算、已分配貨物、緩衝（演示可配置） |

### 3.2 OAG Flight Info API（航班維度與輔助）

OAG **不產出**行李重量／體積；適合作為看板的航班主鍵與上下文 enrichment。

| OAG 欄位（概念） | Response 名稱 | 看板用途 |
| --- | --- | --- |
| 承運人代碼 | `Carrier` | 篩選國泰航班（如 `CX`） |
| 航班號 | `flightNumber` | 組成 `CX257` 等航班鍵 |
| 出發／到達機場、航廈、時間 | `departure` / `arrival` 下 `airport`、`terminal`、`local`/`utc` | **航班日期與航段**展示 |
| 機型 | `aircraftType`；狀態中的 `iata` / `icao` | 推導或對照機型預設重量／體積預算（仍需營運覆寫） |
| 預測／實際座位數 | `totalSeats` 及艙等座位 | 輔助「預計乘機人數」上限或載客率對照；**不可直接當實際 PAX** |
| 準點表現 | `onTimePerformance` | 可支援未來「延誤風險」輔助分數（P2） |
| 航班狀態 | `state`（Scheduled / OutGate / InAir / Landed / InGate / Canceled） | 看板狀態列；取消航班應凍結或降級規劃 |
| 延誤標示 | `outGateTimeliness` / `inGateTimeliness`（Early / OnTime / Delayed） | 風險評級輔助輸入（P2） |
| 貨運艙等能力提示 | `freightClasses`（如 LL、PP） | 體積／ULD 類型參考，非正式容量 |
| 資料更新時間 | `updatedAt` | 與申報 `Data Timestamp` 分開顯示（航班狀態 vs 行李預報） |
| 班表／狀態鍵 | `scheduleInstanceKey` / `statusKey` | 系統對齊用唯一鍵 |

> **審核注意：** 「預計乘機人數」應優先來自訂位／載客系統；OAG 座位是機型座位供給，不是已確認旅客數。演示階段可用固定 PAX（如 100）並標示為演示輸入。

## 4. Attributes 評估總表（含聚合 × 可視化）

圖例：

- **聚合**：能否跨航班／日期／航線／機型做 `SUM` / `AVG` / `COUNT` / 分組
- **可視化**：建議圖種；「KPI 卡」= 大數字 + 趨勢／狀態色，不算圖表亦可

| 屬性 | 推薦度 | 可否衍生 | 聚合可能性 | 可視化可能性 | 審核意見 |
| --- | --- | --- | --- | --- | --- |
| **航班日期與航段** `Flight Date & Leg` | 5 | 可（高低峰、風險） | **強**：主分組維度；可按日／週／航線／出發機場聚合航班數 | 航班選擇器、表格列、日曆熱力（航班量）、航線柱狀圖 | **必選維度**。OAG 可供應程與時刻。 |
| **預計乘機人數** `Estimated PAX Count` | 5 | 可（人均件數／重量） | **強**：跨航班 `SUM`；人均指標需加權勿直接平均覆蓋率 | KPI 卡、與已申報對照的堆疊柱、分艙等條形（若有艙等 PAX） | 分母基準；來源需標註（訂位 vs 演示固定值）。 |
| **已申報／未申報人數** `Declared / Undeclared PAX` | 5 | 可 → 覆蓋率 | **強**：`SUM`；可按航線／日期比較 | **扇形／環形圖**（已報 vs 未報）、堆疊柱、進度條 | 扇圖首選場景之一。 |
| **已知件數** `Declared Piece Count` | 5 | 可（均重） | **強**：`SUM` 件數；`AVG` 需注意只對已申報客 | KPI 卡、航線柱狀、時間序列折線 | 處理工作量指標；勿與「服務訂單件數」雙計。 |
| **預計總重** `Predicted Total Weight` | 5 | 可 → 重量利用率 | **強**：`SUM`；拆「已申報 + 補估」兩層聚合 | KPI 卡、**堆疊柱**（已知／補估）、預算對照條 | 核心約束；須可拆資料來源。 |
| **估計體積** `Estimated Volume` | 5 | 可 → 體積利用率 | **強**：同重量；缺尺寸時聚合應標「不完整」 | KPI 卡、堆疊柱、雙軸對照（重 vs 體） | 外形體積 ≠ 可裝載體積；缺尺寸不可假裝精確。 |
| **資料來源標籤** `Data Source Type` | 5 | 可 → 高信賴度佔比 | **強**：按來源 `COUNT`／重量 `SUM` 佔比 | **扇形／環形**、100% 堆疊柱、圖例色碼 | 旅客填報／基線補估／實測三色建議全看板統一。 |
| **重量規劃餘量** `Weight Planning Margin` | 5 | 可 → 商用載貨空間 | **中**：可跨航班加總，但「負餘量航班數」比總餘量更有營運意義 | KPI 卡（紅／黃／綠）、水壺／進度條、缺口航班排名表 | 公式見 §5；`< 0` 強制警示。 |
| **體積規劃餘量** `Volume Planning Margin` | 5 | 可（混載評估） | **中**：同上 | 同重量餘量；建議與重量餘量並排 | 雙約束並陳，避免只看重量放行。 |
| **資料更新時間** `Data Timestamp` | 4 | 否（業務衍生） | **弱**：可聚合「過期航班數」「最大延遲」 | 時間戳文字、過期徽章、列表排序 | 建議分「行李預報更新」與「OAG 航班狀態更新」。 |
| **航班狀態／缺口提示** `Deficit Status / Alert Flag` | 5 | 可 → 風險評級 | **強**：按狀態 `COUNT`；「紅燈航班佔比」 | 狀態徽章、**扇形**（正常／注意／高風險）、紅燈清單 | 狀態機需寫死規則，避免自由文案。 |

## 5. 衍生指標規格

### 5.1 申報覆蓋率 Declaration Rate — **P0**

| 項目 | 規格 |
| --- | --- |
| 公式 | \(\text{Declaration Rate} = \dfrac{\text{Declared PAX}}{\text{Estimated PAX}}\) |
| 業務價值 | 區分「真實已知」與「系統猜測」；覆蓋率過低應提高緩衝或人工關注 |
| 聚合 | **可**：航線／日期加總時用 \(\sum Declared / \sum PAX\)（加權），禁止對各航班覆蓋率做簡單算術平均 |
| 可視化 | KPI 卡 + 進度條；多航班比較用**柱狀圖**；單航班結構用**環形圖**（已報／未報） |
| 建議閾值（演示可配置） | ≥80% 正常；50–80% 注意；&lt;50% 提高緩衝並標黃／紅 |
| 對齊 | PRD 固定樣例 80%；現有 `ops.coverage` |

### 5.2 重量／體積利用率 — **P0（隨預算輸入）**

| 項目 | 規格 |
| --- | --- |
| 公式 | \(\text{Weight Util.} = \dfrac{\text{Predicted Baggage Weight}}{\text{Weight Budget}}\)；體積同理 |
| 聚合 | **可**：分子分母分別加總再相除；亦可輸出「超閾值航班數」 |
| 可視化 | 對照條、雙環（重／體）、熱力（多航班利用率） |
| 注意 | 分母是**營運行李+貨物可用預算**，不是飛機 MTOW |

### 5.3 總體艙位壓力指數 Capacity Stress Index — **P0 建議**

| 項目 | 規格 |
| --- | --- |
| 公式 | \(\text{CSI} = \max\left(\dfrac{W_{bag}}{W_{budget}},\dfrac{V_{bag}}{V_{budget}}\right)\) |
| 附加輸出 | `bottleneck = weight \| volume \| none`（兩者皆低於閾值） |
| 業務價值 | 一眼判斷本班是重量瓶頸還是體積瓶頸，協助貨運分配 |
| 聚合 | **可**：取航班 CSI 的 `MAX`／`P90`；或統計「重量瓶頸航班數 vs 體積瓶頸航班數」 |
| 可視化 | **單值 KPI + 瓶頸標籤**；多航班用分組柱狀（weight util vs volume util）；瓶頸類型用**扇形** |
| 審核點 | 行李以外的已分配貨物是否計入分子？建議：**CSI 可做兩版**——「僅行李壓力」與「行李+已分配貨物壓力」；預設後者更貼近裝載決策 |

### 5.4 重量／體積規劃餘量 — **P0**

| 項目 | 規格 |
| --- | --- |
| 重量公式 | \(\text{Weight Margin} = W_{budget} - W_{bag} - W_{otherCargo} - W_{buffer}\) |
| 體積公式 | \(\text{Volume Margin} = V_{budget} - V_{bag} - V_{otherCargo}(- V_{buffer})\) |
| 聚合 | 跨航班加總意義有限；優先聚合「負餘量航班數」「平均餘量」「最小餘量」 |
| 可視化 | KPI 卡（負值紅）、前後對照（基線餘量 → 當前餘量）、缺口排名表 |
| 對齊 | PRD 樣例：預算 5000，貨物 1200，緩衝 300；1800 kg 行李 → 餘量 1700 kg |

### 5.5 高信賴度數據佔比 — **P1**

| 項目 | 規格 |
| --- | --- |
| 建議公式 | \(\dfrac{W_{declared}+W_{measured}}{W_{predicted}}\)（亦可用件數或人數口徑，需選定一種並標註） |
| 聚合 | **可**：加權加總 |
| 可視化 | 環形圖、100% 堆疊柱（實測／申報／補估） |
| 審核點 | 「高信賴」定義是否包含旅客自報？建議分級：實測 &gt; 旅客申報 &gt; 系統補估 |

### 5.6 可供商用載貨空間 Commercial Cargo Capacity — **P1**

| 項目 | 規格 |
| --- | --- |
| 建議 | 直接複用「規劃餘量」中可釋出給商貨的部分；若緩衝不可動用，則商貨空間 = 餘量（已扣緩衝後） |
| 聚合 | 同餘量 |
| 可視化 | KPI + 與歷史班次對照柱狀 |
| 審核點 | 命名易被誤解為「已批准可售」；文案建議改為「**商貨規劃可參考餘量**」 |

### 5.7 航班營運風險評級 — **P1**

| 項目 | 規格 |
| --- | --- |
| 建議規則（示例） | **正常**：餘量 ≥ 緩衝閾值且覆蓋率 ≥ 80%；**注意**：餘量偏低或覆蓋率 50–80% 或資料過期；**高風險**：餘量 &lt; 0，或關鍵欄位缺失，或航班 `Canceled`／嚴重延誤且行李未凍結 |
| 聚合 | **強**：各等級航班 `COUNT`／佔比 |
| 可視化 | 狀態徽章、**扇形**、紅燈列表、日視圖熱力 |
| OAG 輔助 | `state`、`*Timeliness`、`onTimePerformance` 可作次要輸入；主因仍應是行李／餘量邏輯 |

### 5.8 人均行李件數／人均重量 — **P1 次要**

| 項目 | 規格 |
| --- | --- |
| 公式 | 件數或重量 ÷ 對應 PAX（建議對已申報與全體分開算） |
| 聚合 | 可；跨航班用加權 |
| 可視化 | 柱狀比較、箱線（若有分布） |
| 用途 | 基線校準與異常航班發現 |

### 5.9 動態調整同步延遲率 Real-time Sync Latency — **P2／系統指標**

| 項目 | 規格 |
| --- | --- |
| 問題 | 您描述的價值對應驗收標準「旅客改 60→70 kg，預測與餘量同步變化」，這是**正確性／即時性 SLA**，不是營運人員日常盯的業務 KPI |
| 建議改寫 | （A）產品驗收項：更新後 ≤ N 秒反映於看板；（B）工程監控：事件產生時間 → 看板可見時間的 p50／p95 延遲 |
| 聚合 | 可（按小時／服務），屬 observability |
| 可視化 | 工程儀表（折線／直方圖）；**不建議**放進員工營運首屏 |
| 審核建議 | 從「亮點衍生指標」移出，改列入「非功能／驗收需求」 |

### 6.3 圖種適配速查

| 圖種 | 適合指標 | 不適合 |
| --- | --- | --- |
| KPI 卡 | 餘量、CSI、覆蓋率、更新時間 | — |

| 表格 | 缺口航班、申報明細、審核清單 | 替代首屏摘要 |

## 8. 功能需求條目（供勾選）

### FR-OPS-M1 維度與篩選

- [ ] 以「航班日期 + 承運人 + 航班號 + 航段（OD）」為主鍵展示
- [ ] 可顯示 OAG 機型、計畫時刻、航班 `state`（若已接入）；未接入時標示演示資料

### FR-OPS-M2 旅客與覆蓋

- [ ] 顯示預計 PAX、已申報、未申報、申報覆蓋率
- [ ] 覆蓋率低於可配置閾值時提示提高緩衝

### FR-OPS-M3 行李需求

- [ ] 顯示已知件數、預計總重、估計體積
- [ ] 重量／體積可拆「已申報／補估／實測」
- [ ] 缺尺寸時體積顯示「待補充」，不輸出假精確餘量

### FR-OPS-M4 規劃約束

- [ ] 計算並顯示重量／體積利用率與規劃餘量
- [ ] 計算 CSI 與瓶頸類型
- [ ] 餘量 &lt; 0 或資料過期／缺失 → 強制警示

### FR-OPS-M5 品質與時效

- [ ] 資料來源標籤與（P1）高信賴度佔比
- [ ] 行李預報更新時間；可選顯示 OAG `updatedAt`
- [ ] 旅客更新申報後，看板使用最新版本且不重複計件

### FR-OPS-NFR1 同步（原「延遲率」）

- [ ] 申報保存成功後，營運彙總在 **≤ 2 秒**（演示可同步）內反映新重量與餘量
- [ ] 工程環境可記錄端到端延遲；不作為員工首屏 KPI

## 9. 審核問題清單（請您拍板）

1. **預計乘機人數**正式來源：訂位系統／DCS，還是演示固定值？是否允許用 OAG `totalSeats` 當上限參考？
2. **CSI 分子**是否包含「已分配其他貨物」？
3. **高信賴度**是否包含旅客自報，或僅實測？
4. 「可供商用載貨空間」是否改名為「商貨規劃可參考餘量」，以避免合規／業務誤解？
5. 首期是否只做**單航班看板**，多航班聚合留二期？
6. OAG 是否納入黑客松演示範圍，或僅作後續接入設計？
7. 風險評級規則閾值是否採用 §5.7 示例，或由營運另行提供？
